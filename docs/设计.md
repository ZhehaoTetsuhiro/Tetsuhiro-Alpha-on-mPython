# 设计：机器口径与取舍

> 这份文档是「板上这台机器到底是个什么东西」的**唯一权威列表**。
> 标 **[待确认]** 的是我按自己的理解定的，你点头/纠正之后我就把标签去掉。
> 实现与规范的差距（哪些指令没做）看 §3。

---

## 1. 一句话

板上跑的是 `../Tetsuhiro-Alpha`（TH128I）的**板用子集**；程序是一串四进制数字，
16 个数字一条 32 位指令；主机 I/O 沿用 `tthr` 的 tohost 约定。

---

## 2. 程序怎么摆

| 项 | 定为 | 为什么 |
|---|---|---|
| 数字 | `0 1 2 3`，屏幕上一行 16 个 | 一行 = 一条指令 |
| 键位 | `P=3 Y=2 T=1 H=0` | 需求表原文 |
| 位序 | 一行左边第一个数字是 `bit[31:30]`，最右是 `bit[1:0]` | 一行就是"一个四进制写的 32 位数"，读起来跟十进制数一个方向 **[待确认]** |
| 存储 | 小端字节流，每 4 位数字 = 1 字节（`4^4 = 256`）；指令按小端落进内存 | 和 `.tthr` 的格式一致 |
| 长度 | 最多 4096 位 = 256 条指令 | 板上堆放得下；且是 16 的整数倍 |
| 存档 | 文本文件 `ta.prog`，`0-3` 加换行；读的时候空白和 `#` 注释一律跳过 | 电脑上能直接看/改 |

一条指令的对齐是**硬性**的：`pc` 不是 4 的倍数就报错（没有压缩指令，见 §3）。

---

## 3. 指令集：做了什么，没做什么

**做了**：TH128I 基础整数（load/store、OP、OP-IMM、分支、JAL/JALR、LUI/AUIPC、
FENCE）+ M 扩展（乘除）。寄存器、PC、内存地址都是 **128 位**。

**没做**（碰到编码就报错，绝不猜着执行）：

| 没做 | 为什么 |
|---|---|
| CSR / 特权级 / 陷阱 / `xRET` | 板上没有特权级可切；要做"真的陷阱"就得把四级特权、`xstatus/xepc/xcause`、委托链全搬来，几十 KB 代码换一个岛上用不到的功能 |
| 压缩指令（C 扩展） | **它会破坏"16 位 = 一条"**：C 指令是 16 位 = 8 个四进制数字，取指要在 2 字节边界上动态切换。需求里"长按挪 16 位 = 一行"隐含了 32 位定长 **[待确认]** |
| 浮点（F/D）、向量（V） | 软浮点/向量在板上是另一个数量级的代码；需要再说 |
| A 扩展（原子） | 单 hart，板上没有别的线程去抢内存 |
| T 扩展（信任根） | 没有硬件根密钥 |

**一处有意偏离参考实现**：`tthr` 里跑过镜像末尾会读到 0、触发非法指令；
板上**跑过最后一条指令就算正常结束（END）**。理由是"忘了写停机"在板上太常见了，
报 ERR 不如安静结束；反过来，写程序时真跑飞了也不会给你一个吓人的错。
**[待确认]**

## 4. 输入输出

沿用 `tthr` 的约定，只多一个输入口：

| 地址 | 干什么 |
|---|---|
| `0x1000` 写 | `v & 1` → 低 8 位当字符打印；否则以退出码 `v >> 1` 结束 |
| `0x1004` 读 | 把下一个输入字符给 `rd`；**队列空就停下来等用户敲** |

* 一次 `lw` 取走**一个字节**，读完把 `pc` 退回这条指令（所以重入是安全的）。
* 输出按 `\n`(10) 分行；屏幕上只留最后几行（`OUT_LINES_MAX`），串口打全份。

`0x1004` 是我定的 **[待确认]**。要不要改成别的形式（比如用 `ECALL`、
或者干脆学 `fromhost` 的 RISC-V 测试套件写法），你说。

## 5. 板上输入的解读规则

需求原文两条，我的实现：

### 字符模式

* `P Y T H` 敲出来的是**四进制写的 ASCII 码**：`T H H T` = 4³+1 = 65 = `A`。
* `O` 确定 → 往程序嘴里塞**一个字节**（码值 & `0xff`）。
* 空行按 `O` 什么也不发（不会误塞一个 NUL）。

### 数字模式

* `P Y T H` 敲四进制数字，`O` 确定 → 转成**十进制数字**送进程序。
  `T` `Y` = 6 → 送 `6` 这个字符。
* **开头 `HH`**（两个 0）当负号，并被吃掉：`H H T Y` → `-6`。
  单个前导 0 不算负号（`H T` → `1`）。 **[待确认]**：四进制里前导 0 本来没意义，
  所以拿 `00` 当符号位是安全的；但 `HH` **单独**两个键我不想让它变成 `-0` 的歧义 ——
  现在的实现是"只要开头两个 0 就是负号"，也就是 `HH` = `-0`。
* **`A+B` 同按**插小数点：`T Y` `.` `T` → `6.3`；
  负号带小数 `H H T H` `.` `Y` → `-4.2`。
* 小数点只允许一个，且只在数字模式里有。

**[待确认]** 上面这几条（尤其"HH = 负号"和"一次 O 把整行字符全塞给程序"）是
我从两行需求里推的，措辞不同就换个做法。

### 运行中按键

* 程序**正在跑**（不在等输入）时：按任意键 = 停。这时候 `A+B` 也只是停，
  不会顺手把程序清空（这条我写了测试盯着）。
* 程序**卡在输入口上**时：八个键按 §「运行界面」表走，不会"按一下就把整个程序停掉"。

## 6. 内存与性能

* 内存是**稀疏页**（4 KiB 一页，页内 256 字节；没写过的页读 0）。
  这样"栈在 0x3000、数据在 0x4000"这种写法不会一次吃掉一大块连续堆。
* 步数上限 30 万（`ta_app.STEP_LIMIT`），一次 slice 跑 800 步就回去扫一次按键，
  所以死循环按一下就下来。
* 每次跑都 `gc.collect()`（每 200 tick 一次）：板上堆只回收、不搬家，
  碎一点就 `MemoryError`。

## 7. 和 TTL 的关系

TTL 是**三进制小语言**（9 条指令、跑在自己的 VM 上）；TA 是**机器码本身**
（TH128I 的板用子集）。两边共享的是同一套"掌控板工程学"：
`MpythonHW/SimHW` 两层硬件、`KeyScanner`（短按/长按/连发/组合键）、
SimHW 剧本驱动测试、按文件拆分保内存。这些是照着 TTL 那套做熟的形状来的。

## 8. 编辑画面的两种看法（已实现）

`A+B` 快点一下切换，**程序一个字都不改**：

| 视图 | 状态行 | 每行画什么 |
|---|---|---|
| 数字（默认） | `E  48/ 224` | 16 个四进制数字；光标用下划线 |
| 反汇编 | `D  48/ 224` | 一条指令的助记符；左边 `>` 指着光标那条 |

反汇编用的是 `ta_core.decode()` —— 和电脑端 `ta.py dis` **同一份代码**，
所以两边不可能对不上。屏幕只有 16 格宽，所以反汇编视图**不画地址**：
`addi x10, x0, 5` 正好 15 格，加上 `>` 就是 16。

两种视图里都能改程序（改的是同一份缓冲），所以可以"看一行数字、看一眼反汇编"
地对着改。
