## 1. 问题有多大（先看真实数字）

一条指令 = 16 个四进制数字 = **16 下按键**。而且这 16 个数字不是"看得懂的东西"，
它是一条 32 位指令的四进制写法，得先在脑子里把 RISC-V 那套位域拼出来：

```
addi a0, x0, 5     →  0x00500513  →  0000110000110103
                      键：H H H H  T T H H  H H T T  H T H P

sw   x0, 0(x0)     →  0x00002023  →  0000000002000203
add  a2, a0, a1    →  0x00b50633  →  0000231100120303
```

`0000110000110103` 这串东西，**没有任何人能一眼看出它是 `addi a0, x0, 5`**。
更要命的是 `rd` 藏在 bit[11:7]、`rs1` 在 bit[19:15]、`imm` 在 bit[31:20]，
每写一条都得做一次"移位 + 掩码"的心算。

这就是"有所不便"的准确含义：不是按得多，是**按的东西无法检查**。

---

## 2. 一条硬前提：板上的**程序格式不许动**

不管走哪条路，板上那份程序还是**一串四进制数字**。理由：

1. 编辑器的光标、长按挪 16 位、"一行 = 一条指令"、存档、`--program` 推送，
   全都建立在"程序 = 数字串"上；换格式等于把这些全推倒。
2. 掌控板跑起来只剩 ~96 KB 堆，MicroPython 编译时峰值又正比于**单个文件**的大小。
   在板上再养一个汇编器（词法 + 两遍符号表 + 编码器）是实打实的内存。

**所以"输入汇编"要解决的是"怎么把汇编变成那串数字"，不是"把汇编存进板子"。**
这一条定了，方案就只剩下面几种。

---

## 3. 四个方案

### 方案 A —— 电脑汇编，推送上板（**推荐**）

电脑上写 `.s`，汇编成四进制数字，从串口写进板子的 `ta.prog`。

```bash
python3 tools/ta.py asm  examples/hello.s -o examples/hello.ta  # 汇编
python3 tools/ta.py push examples/hello.s                       # 汇编 + 写进板子 + 读回校验
python3 tools/ta.py pull -o 备份.ta                              # 从板子读回来 + 反汇编
python3 tools/ta.py keys examples/hello.s                        # 告诉你"在板上该按哪 16×N 个键"
```

**已经做好了**（`tools/ta.py`，这一轮就在仓库里）。汇编语法就是
`../Tetsuhiro-Alpha` 那套 `tthr asm` 的语法，连伪指令和指示字都一样，所以
电脑上跑通的程序**搬到板上不需要改一个字**。

* 好处：板上代码一行不增；汇编器语义直接对齐参考实现；`keys` 还能当"手抄说明"。
* 代价：**要插电脑**。

### 方案 B —— 板上反汇编显示（**推荐，和 A 一起做**）

编辑器照旧编辑数字，但屏幕上**把当前这条指令翻译成人话**。

已经做了半步（`src/ta_app.py` 的 `mnemonic_here()`）：状态行右边显示光标所在
那条指令的助记符，**不占任何按键**：

```
┌──────────────────┐
│E  48 / 112  LOAD │   ← 状态行：位置 + 存档标签（LOAD/UNSAV/SAVED）
│0000110000110103  │   ← 你现在敲的这条
│...               │
└──────────────────┘
```

再往前一步是"整屏反汇编"：屏幕切成 8 行，每行左边 16 位数字、右边助记符
（像 TTL 右边那列）。这样**一边敲一边能核对**，"敲错了却看不出来"这件事就没了。

> 按键表已经排满了（八个键短按/长按各有用处），所以整屏反汇编得占一个新模式键。
> 三个候选见 §5。

* 好处：**不用改程序格式、不用改存档、不占内存**（反汇编器只有几十行，
  而且 `ta_core.decode()` 已经有了）；它治的是"看不见"这个根本毛病。
* 代价：屏幕一行只有 16 格，数字和助记符得争地方。

### 方案 C —— 板上结构化汇编器（"字段填空"，**建议先不做**）

真要在板上敲汇编，**不应该敲字母**（八个键敲 26 个字母是灾难）。可行的是
"选模板 + 填字段"：

```
┌──────────────────┐
│A addi rd,rs1,imm │   ← 长按 O / N 在模板表里前后翻
│rd  = 10  (a0)    │   ← P Y T H 填这一段的四进制数字
│rs1 = 00  (zero)  │   ← A 跳下一段，B 退格
│imm = 05          │
└──────────────────┘   A+B 把这条展开成 16 位数字、追加到程序里
```

* 板上存一张十几条的模板表（`addi/add/sub/lw/sw/lui/jal/beq/bne/...`），
  每条记 opcode / funct3 / funct7 和字段顺序；填完由板上现拼 32 位字。
* 好处：不用敲 16 位裸数字，而且**字段是看得见的**（rd/rs1/imm 各填各的）。
* 代价：
  * 模板表 + 编码器要吃板上内存（估 1~2 KB，还得跟编辑器争）；
  * **标签做不到**（要两遍符号表）。跳转只能自己数地址填立即数；
  * 编辑模式多一套状态机，需求表那八个键在"汇编模式"下要重新排一遍。
* 结论：**收益不如 A**，除非"不插电脑"本身就是你的要求。

### 方案 D —— 极简宏（伪指令键）

只给最常用的几条做"快捷键"。问题是需求表里八个键短按/长按**全都排满了**，
加宏就得改按键表或者加新组合键 —— 而且它仍然没有标签。把它当 C 的缩水版，
不单独推荐。

---

## 4. 推荐：A + B

一句话：**"怎么写"交给电脑，"写成什么样"板上看得见。**

| | A（电脑汇编） | B（板上反汇编） |
|---|---|---|
| 解决 | 生成机器码 | 核对机器码 |
| 板上代价 | 零 | 零（反汇编器已有） |
| 要不要动按键表 | 不要 | 整屏反汇编要；状态行助记符不要 |

两条一起，日常流程是：

1. 电脑上写 `prog.s`，`ta.py run prog.s` 跑通；
2. `ta.py push prog.s` 写进板子；
3. 板上按 `A` 跑；想改几个数字，就在板上改，状态行会告诉你改成了哪条指令。

**仍然保留"裸敲 16 位数字"这条路** —— 那才是这个项目"直接在机器码上编程"的味道，
汇编只是给长程序和查错用的。

## 5. 三个具体决定（**已定**）

### 5.1 整屏反汇编的开关放哪（三选一）

**结论：候选 ① 也没采纳** —— 反汇编视图的开关落在 `A+B` 快点一下上
（`A+B` 那条时间轴：快点一下换显示 / 0.7s RELOAD / 1.5s CLEAR），
长按 `B` 的"退格连发"原样留着。下表是最初的三个候选，留作决策记录：

需求表已经排满，只能挑一个：

| 候选 | 具体 | 影响 |
|---|---|---|
| ① 长按 `B` | 编辑界面长按 `B` = 背光/显示切换，从"每 0.1s 退格"里让出来（**没采纳**） | 退格连发就没了（短按退格还在） |
| ② `A+B` 快点一下 | 现在它是 RELOAD | RELOAD 要挪到别处（比如长按 `A` 保存 和短按 运行 之间已经没缝） |
| ③ 不做整屏 | 只保留状态行的助记符 | 最省事，但一行只能看一条 |

### 5.2 反汇编显示到什么程度

**结论：选第二个** —— 屏幕上**一条指令占一行、显完整操作数**（`addi x10, x0, 5`），
左边一格用 `>` 指着光标所在的那条。**状态行右角后来给了存档标签**
（`LOAD`/`UNSAV`/`SAVED`，见 `docs/设计.md` §8）—— 16 格摆不下"数字 + 标签 +
助记符"三样，助记符在数字视图里让位了（反汇编视图里整行都有）。
反汇编视图**不画地址**：屏幕 16 格，`addi x10, x0, 5` 正好 15 格 + `>` = 16。

### 5.3 板上的汇编（方案 C）要不要做

**结论：不做，这条归档。** 方案 C 需要按 §3-C 的样子出按键详表 + 内存估算，
再做一遍板上装配器（模板表 + 编码器，估 1~2 KB 堆），而且标签仍然做不到；
这一轮不占这个预算。要是哪天"不插电脑"变成硬要求，再翻出 §3-C 接着谈。

## 7. 附：为什么不干脆把程序存成汇编

因为掌控板要跑的是**机器码**这个项目本身。存成汇编就得在板上养编译器，
而板子只有不到 100 KB 堆 —— 那是把 PC 的活搬到板上来干。
**"汇编是笔，机器码是纸"**：纸永远是那串四进制数字。
